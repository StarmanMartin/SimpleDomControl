any framework or library except SDC (see [../agents.architecture.md](../agents.architecture.md), "Condition `free`").

## Findings

1. **SDC with the agent kit costs about the same as plain Django** (2.17 vs 2.04 USD, within the run-to-run
   spread); SDC *without* the kit costs about twice as much. The kit is what makes SDC competitive for AI agents.
2. **SDC is cheaper where it has the feature built in.** MCP access with a token: 0.20 vs 0.36 USD and 30 s vs
   80 s — the free agent wrote a whole MCP app (token model, management command, views; 15 files). Fixing the
   broken widget and the model with validated forms also need fewer turns with SDC.
3. **Plain Django is cheaper for simple pages.** A list page costs 0.15 USD in plain Django vs 0.27 with SDC: one
   view and one template, against an SDC controller pair (view, template, JS, SCSS, organizer, URL).
4. **All free agents chose plain Django templates and vanilla JS** (`fetch`); none added htmx, React or Python
   packages. They wrote tests unasked in 9 of 10 runs (more output tokens).
5. **SDC runs carry much more context per turn**: 21k input tokens per turn with the kit (24k without) vs 13k in
   the free runs. Hypothesis: agents read more text in SDC projects — generated controller files with long
   boilerplate comments, skill files, `sdc_agent` output. Transcripts of free runs would confirm it; if true,
   trimming the generated boilerplate (`sdc_cc` / `sdc_new_model` templates) would cut every SDC task.

## Not measured

The checks test the visible contract, not what each solution offers beyond it: SDC's controllers come with live
model sync, permission hooks, the AI assistant and an MCP server with privileges and revocable tokens; the free MCP
endpoints are hand-written. Plain Django is also far more common in the model's training data than SDC.
