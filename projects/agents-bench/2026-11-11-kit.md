**Target of M3 met**: ≥ 30 % fewer input tokens at full success — reached −63 %, with fewer turns for every task.

## Findings

1. **The kit is what pays off.** With the commands alone (B) the agent found `sdc_agent` in 3 of 18 runs
   (through `manage.py help`), and the total fell by only 15 %. With `AGENTS.md` naming them (C), 17 of 18 final
   messages mention `sdc_agent`, and every task gets cheaper.
2. **Framework pitfalls benefit most.** `fix_counter` fell from 38 to 7 turns and from 0.79 to 0.15 USD:
   `sdc_agent check` reports both planted bugs with their fix, so the agent no longer guesses how SDC binds events.
3. **Scaffolding tasks halve.** `controller_list` and `server_call` need 9–12 turns instead of 20–27.
4. **Cost falls less than tokens (−50 % vs −63 %).** The kit is new context that is written to the cache once per
   run (cache writes are 7 % of the input in C, 4.4 % in A) and cache writes cost more than reads. Short runs
   carry this fixed cost: `document` and `mcp_token` gained least in cost.
5. **No agent edited the kit files** (no changes under `.claude/` or to `AGENTS.md`).

## Limits

One model, one day, 3 runs per task and condition (spread within a task is up to ±40 %, see the raw data); the
tasks are small and close to what the kit describes. Transcripts were not recorded, so which files and skills
the agents read is not known — needed for tuning (M3, WP3.2).
