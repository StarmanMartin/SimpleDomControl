# Architecture: fewer tokens for AI agents

Companion to [agents.plan.md](agents.plan.md) (what and when); this file says how the parts are built and how
they fit together. Decisions D1–D5 are taken as proposed (2026-11-11):

- D1: skills in `.claude/skills/sdc-*/SKILL.md`, `AGENTS.md` as the tool-neutral entry point, `CLAUDE.md` =
  `@AGENTS.md`
- D2: one command `manage.py sdc_agent` with sub-commands
- D3: `sdc_init` installs the kit by default (`--no-agent-kit` to skip); `sdc_agent kit --update` refreshes it
- D4: `AGENTS.md` has a generated block between markers; the rest is hand-editable and kept on update
- D5: the benchmark agent is Claude Code headless (`claude -p --output-format json`)

## Overview

```
                         ┌────────────────────────── SDC project (generated by sdc_init) ──────────────────────────┐
 coding agent  ──reads──►│ AGENTS.md (≤ 800 tokens, always loaded)      CLAUDE.md → @AGENTS.md                      │
 (Claude Code, …)        │ .claude/skills/sdc-*/SKILL.md  (loaded on demand, matched by description)                │
                         │        └── references/*.md     (read only when the skill says so)                        │
               ──runs───►│ python manage.py sdc_agent overview | where | check | new-controller | new-model | …    │
                         └───────────────────────────────────────────────────────────────────────────────────────────┘
                                          ▲ templates + version stamp            ▲ library code
                         ┌────────────────┴───────────────┐      ┌────────────────┴─────────────────────┐
                         │ sdc_core/template_files/agent_kit│      │ sdc_core/agent/ (project map, checks, │
                         │   AGENTS.md.txt, skills/…        │      │   kit installer, terse output)        │
                         └────────────────▲───────────────┘      └──────────────────────────────────────┘
                                          │ reference slices extracted from the Sphinx docs (WP2.4)
                                     docs/*.rst

 dev only:  scripts/agent_bench/  ──creates──► fresh seeded projects ──runs──► claude -p … ──► results/*.jsonl
```

## 1. `manage.py sdc_agent` (M1)

- **Command**: `sdc_core/management/commands/sdc_agent.py`, argparse sub-commands. Thin: parses arguments, calls
  the library, prints.
- **Library** `sdc_core/agent/`:
  - `project_map.py` — one data structure of the project: apps → controllers (tag, view class + file:line,
    template, JS, SCSS, organizer line, URL) and SdcModels (fields, forms, permissions hooks, MCP exposure, JS
    model). Built from the same sources as `sdc_get_controller_infos` / `sdc_get_model_infos` (those commands
    then use it too, so there is one implementation).
  - `checks.py` — consistency checks over the project map; each check returns `Problem(path, line, message,
    fix)`. Static JS checks use regular expressions on the controller files (no JS parser dependency).
  - `scaffold.py` — `new-controller` / `new-model`: call the existing generators (`sdc_cc`, `sdc_new_model`,
    `sdc_make_model_js`, `sdc_update_url`) in-process with all arguments given, then return the changed files.
  - `runner.py` — `test` / `build`: run pytest, Jest (`yarn sdc_test`) or the asset build as a subprocess, write
    the full log to `.sdc_agent/logs/<name>.log`, parse and return a summary.
  - `output.py` — terse formatting: relative paths, one line per item, `--json` for machine use.
- **Rules for all sub-commands**: never prompt; missing input → `CommandError` naming the flag; output ≤ ~40
  lines by default; exit code ≠ 0 when something needs fixing (`check`, failing `test`).
- **No prompts anywhere (WP1.1)**: `sdc_cc`, `sdc_new_model`, `sdc_init`, `sdc_teach` read input only if
  `sys.stdin.isatty()` and `--no-input` is not set; otherwise they fail with the flags to pass.

## 2. Agent kit (M2)

- **Templates**: `sdc_core/template_files/agent_kit/`
  - `AGENTS.md.txt` with `<!-- sdc:generated:start -->` / `<!-- sdc:generated:end -->` around the project block
    (apps, models, controllers count, commands)
  - `CLAUDE.md.txt` (`@AGENTS.md`)
  - `skills/sdc-controller/SKILL.md`, `skills/sdc-model/SKILL.md`, … each with YAML front matter (`name`,
    `description` naming the trigger words) and `references/*.md`
- **Installer** `sdc_core/agent/kit.py`, used by `sdc_init` and `sdc_agent kit install|update|check`:
  - writes the files, records a manifest `.claude/skills/.sdc-kit.json` (SDC version, file → hash of the
    generated content)
  - `update` overwrites files whose hash is unchanged since installation, keeps edited ones (reports them), always
    regenerates the marked block of `AGENTS.md` and keeps the rest of it
  - `check` compares the manifest's version with the installed SDC version
- **Reference slices (WP2.4)**: the Sphinx pages mark reusable parts (`.. sdc-agent-ref: events` … `..
  sdc-agent-ref-end`); `scripts/build_agent_refs.py` copies them into the kit templates as Markdown. The slices
  are committed; a test fails when they differ from the docs.
- **Kit test**: `pytests/test_agent_kit.py` installs the kit into a temporary project and checks that every
  `manage.py <command> <flags>` in the kit parses with the real argparse parsers, every mentioned path exists
  after `sdc_init`, every skill has front matter and stays below the size limit.

## 3. Benchmark harness (M0, dev only, not shipped)

Location: `scripts/agent_bench/` (repository only; the poetry package list does not include it).

| Module | Job |
|---|---|
| `bench.py` | CLI: `run` (tasks × conditions × runs) and `summarize` |
| `project.py` | builds a fresh seeded project per run |
| `tasks.py` | the tasks: id, prompt, extra seed step, check |
| `agent.py` | runs the agent headless and parses its JSON result |

**Seeded project** (`project.py`), built in a new temporary directory outside any repository (no foreign
`CLAUDE.md`/`AGENTS.md` above it):
1. copy `pytests/test_django_project(DUMMY)`, delete its `db.sqlite3`, run `sdc_init`
2. `startapp library`, add it to `INSTALLED_APPS`, write the models `Author` and `Book` (SdcModels with forms)
3. generate the controllers the tasks need with `sdc_cc` (e.g. `book_detail`), apply task-specific seeds
4. `makemigrations`, `migrate`, create user `admin` and a few books
5. condition `kit`: install the agent kit (from M2 on; until then the condition is refused)
6. `git init` and commit, so the agent's changes can be measured with `git diff --stat`

**Agent run** (`agent.py`), in the project directory, with the project's Python first on `PATH`:
```
claude -p "<task prompt>" --output-format json --model <model>
       --permission-mode acceptEdits --allowedTools "Read,Edit,Write,Glob,Grep,Bash(python:*),…"
       --setting-sources project,local
       --strict-mcp-config --no-session-persistence --max-budget-usd <cap>
```
- `--setting-sources project,local` and `--strict-mcp-config` keep the user's own settings, hooks and MCP
  servers out; the user's global `~/.claude/CLAUDE.md` is still read in both conditions (equal for both; noted
  in results).
- Permissions (`--permissions`): `restricted` (default) allows the file tools (edits only inside the project) and
  `python`, `ls`, `cat`, `head`, `git status|diff`; everything else is denied without a prompt. `bypass` switches
  all checks off and is meant for a container or VM only. Note that `python` still runs arbitrary code with the
  developer's rights: start the benchmark only with the task prompts of `tasks.py`.
- Recorded from the JSON result: `num_turns`, `usage` (input, cache creation, cache read, output tokens),
  `total_cost_usd`, `duration_ms`, `is_error`, the final message.

**Checks** (`tasks.py`): plain Python functions that run after the agent in a subprocess of the project
(`DJANGO_SETTINGS_MODULE` of the project): file/organizer/URL assertions, Django test client requests to the
controller views and server calls, model and form behaviour, MCP calls. A check returns `(passed, details)`. No
browser and no Node build needed, so a run takes minutes, not tens of minutes.

**Results**: one JSON line per run in `projects/agents-bench/results/<date>-<condition>.jsonl` (task, condition,
run, model, SDC version, kit version, usage, turns, cost, duration, check result, files changed). `summarize`
prints medians per task × condition and the change between conditions; it also writes a Markdown table for the
plan.

## 4. Runtime follow-ups (M4)

- `SDC_MCP['instructions']` (`index` | `short` | `none`) in `sdc_core/mcp/view.py::_instructions`.
- `fields` argument of `model_load` / `model_get` → `model_actions.load_page(…, fields=…)` → serializer field
  subset (validated against the exposed fields); REST `?_fields=` uses the same path.
- Assistant: compare `SDC_AI_SKILL_MODE` with the existing `sdc_eval_ai`, no new code expected.

## 5. Tests

| Part | Test |
|---|---|
| no prompts, `sdc_agent` sub-commands | `pytests/test_sdc_agent.py` (in a generated project like `test_cc`) |
| kit install/update/check, kit consistency | `pytests/test_agent_kit.py` |
| reference slices up to date | `pytests/test_agent_kit.py` |
| benchmark tasks: seed and check work | `scripts/agent_bench` self-test (`bench.py selftest`: seed every task, apply the known solution, the check must pass; without it, it must fail) — no agent, no API costs |
