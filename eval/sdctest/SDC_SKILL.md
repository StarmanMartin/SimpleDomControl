# SdcTest UI map

Generated by `manage.py sdc_teach` on 2026-11-03. Crawled as: anonymous, user root. All paths are relative to the site root.

## How to operate this app

- The app is a single page. Views are SDC controllers nested by the `sdc-navigator`; the URL path lists them separated by `~`: `/~parent-view~child-view`.
- Arguments follow after `~&` as `key=value` pairs joined by `&`: `/~main-view~&id=5`. A key may be prefixed with the view depth (`1.id`, `2.id`) to target one view of the path; arguments are handed to the view as `data-*` attributes / `this.params`.
- Relative paths: `..` goes one view up, `*` keeps the current view at that depth, `.` is the current path (e.g. `..~other-view`).
- Navigate in the browser with `window.sdcNav.goTo("/~view-a~view-b", {key: value})` or open the URL directly; links with class `navigation-links` do the same.
- Buttons call controller methods named in their `sdc_click` attribute (`sdc_click="method"`); `events.click[".selector"]` marks handlers registered in the controller `events` list.
- A view is ready when `window.sdcNav && !window.sdcNav._is_processing` and no `.sdc_sub_detail_container.loading` element exists.
- Server calls (`this.serverCall(...)`) execute methods of the matching `SDCView` on the server; model-socket calls load/save model data.
- Buttons marked "skipped" were not executed by the crawler because they look destructive (delete/logout/save/submit); their effect is unknown — confirm with the user before clicking them.
- Forms were not submitted automatically; "submitted by developer" shows what a manual submit did, "not submitted" means the outcome is unknown.
- A view showing `sdc-error 403` needs a logged-in user with the right permissions.
- All SdcModel WebSocket traffic (`/sdc_ws/model/<Model>`) was recorded per controller: "Model socket (on load)" lists what each controller requests when the view opens, buttons and forms list what they trigger, as `Model.event(args)` with the `model_query` filter keys. `connect` subscribes to live updates of the filtered rows; `load`, `save`, `create`, `delete`, ... read or write data.

### `<sdc-model-form>`

Generic create/edit form for one record of an SDC model, generated from the model's server-side form; saves via the model socket.

- Arguments: `model` (required) is the SDC model name; with `pk` (or `id`) it edits that record, without it it creates a new one (e.g. `/~sdc-model-form~&model=Author&pk=3`).
- Edit mode: every field change is saved automatically, there is no save step; with `form_name=<name>` a named alternative form of the model is used, and with `auto_save=false` changes are only stored when the save button (`button_text`, default "Save") is pressed.
- Create mode: "Create" creates the record and then navigates to `next` (default `..`, one level up); `reset_on_save=true` instead clears the form for another entry, `editing_after_save=true` switches to editing the new record.
- After a successful save of an existing record the form navigates to `next` if given.
- Other optional arguments: `form_header` (heading text) and `filter` (selects the record to edit instead of `pk`).
- Validation errors are shown at the fields; who may create or edit is decided by the model's server-side permissions.
- Also used as a mixin by app-specific form controllers.

_app `sdc_tools`, server view `sdc_tools.sdc_views.SdcModelForm`, Django URL `/sdc_view/sdc_tools/sdc_model_form`_

### `<sdc-navigator>`

Root navigation frame of an SDC app: owns the URL, the nested views and the breadcrumb; there is one per page and it is exposed as `window.sdcNav`.

- URL scheme: `/~<tag>~<child-tag>~&key=value&...`. Each `~` segment is a controller tag rendered nested inside the previous one; arguments after `~&` are passed to the views as data attributes (`N.key=value` targets only the view at depth `N`, plain `key` applies to the deepest one). Relative paths (`.`, `..`, `*` = keep the current segment at that depth) are resolved against the current path.
- An empty path opens the controller named in its `default-controller` argument; a view container with its own `data-default-controller` opens that child automatically.
- Links with the class `navigation-links` are handled client-side without page reload; `window.sdcNav.goTo('<path>', {args})` (or triggering the `goTo` event) navigates programmatically. Browser back/forward works.
- An unknown tag in the path shows `sdc-error 404` instead of the view. Some containers open their view in a modal; closing the modal navigates back one level.
- Links marked as login-only/logout-only are shown or hidden depending on whether a user is logged in; the `login`/`logout` events reload the whole page.

_app `sdc_tools`, server view `sdc_tools.sdc_views.SdcNavigator`, Django URL `/sdc_view/sdc_tools/sdc_navigator`_

Invisible global helper that loads the `SdcUser` record of the logged-in user (nothing for anonymous visitors) and provides it to other controllers on request; it shows no content and has no actions.

_app `sdc_user`, server view `sdc_user.sdc_views.SdcUser`, Django URL `/sdc_view/sdc_user/sdc_user`_

### `<sdc-user-nav-btn>`

User area for the navigation bar: shows "Login" and "Register" links when nobody is logged in, and an "Edit <username>" link (opens the user's own `SdcUser` in `<sdc-model-form>`) plus `<sdc-logout>` when a user is logged in. It refreshes itself after login and logout.

_app `sdc_user`, server view `sdc_user.sdc_views.SdcUserNavBtn`, Django URL `/sdc_view/sdc_user/sdc_user_nav_btn`_

### `<staff-and-admin>`

Test fixture of the framework's test project for the group/staff access check; it shows only a static test heading.

- May be opened by logged-in staff users and superusers; no group grants access.
- Anyone else (anonymous or without permission) is redirected to `<sdc-login>`, with `next` pointing back to the parent view.
- Shows and changes no data.

_app `main_test`, server view `main_test.sdc_views.StaffAndAdmin`, Django URL `/sdc_view/main_test/staff_and_admin`_

## Data models

SDC models are loaded and saved over the model WebSocket (`this.querySet("Name", {filter})` in a controller).

### `Author` (main_test)

Demo/test model of the framework's test project: an author of `Book` records.

- `name` (text, max. 255 characters) and `age` (integer, years); both required.
- Has no permission checks: anyone, even anonymous users, may read, create, edit and delete authors.
- Deleting an author also deletes all of that author's `Book` records.
- The list search matches `name` or the title of one of the author's books.
- Calling the `call_echo` / `call_async_echo` server calls of `<main-view>` creates an extra author `XX FF` (age `2`).

Fields: `id` (BigAutoField), `name` (CharField), `age` (IntegerField)

### `Book` (main_test)

Demo/test model of the framework's test project: a book with a title, written by one `Author`.

- `title` (text, max. 255 characters); `author` → `Author` (required).
- Has no permission checks: anyone, even anonymous users, may read, create, edit and delete books.
- Deleted automatically when its `Author` is deleted.
- Besides the full form there is a named form `test` that edits only `title`.
- The list search matches `title` or the author's `name`.
- Edited in `<book-edit>`.

Fields: `id` (BigAutoField), `title` (CharField), `author` → `Author`

### `BookContent` (main_test)

Demo/test model of the framework's test project: an uploaded file that belongs to one user.

- `text`: the uploaded file; `user` → the owning user.
- If `user` is left empty on save, the currently logged-in user becomes the owner.
- Only logged-in users may access it, and each user sees and changes only their own records.
- Deleting the user also deletes the user's `BookContent` records.

Fields: `id` (BigAutoField), `user` → `SdcUser`, `text` (FileField)

### `SdcUser` (sdc_user)

A user account of the site (the project's Django user model); one record per person who can log in.

- `username` (unique, used to log in), `first_name`, `last_name`, `email`; `is_staff`, `is_superuser`,
  `is_active`, `groups`, `date_joined`, `last_login` as in Django's standard user.
- `email_confirmed`: `true` once the user followed the link in the confirmation e-mail (`<sdc-confirm-email>`).
- The password is never sent to the client; it is changed with the `password_form` (`<sdc-change-password>`)
  or reset by e-mail (`<sdc-password-forgotten>`).
- Anyone may create an account (registration in `<register>`). By default a logged-in user can read and
  edit only their own record (`username`, names, `email`); superusers can see and edit all users, and only
  superusers may delete users.
- Saving a new or changed `email` resets `email_confirmed` to `false` and sends a confirmation e-mail to
  that address (link valid for 3 days).
- Edited in `<sdc-model-form>` via the "Edit <username>" link of `<sdc-user-nav-btn>`; `<sdc-user>` loads
  the current user's record.

Fields: `id` (BigAutoField), `last_login` (DateTimeField), `is_superuser` (BooleanField), `username` (CharField), `first_name` (CharField), `last_name` (CharField), `email` (CharField), `is_staff` (BooleanField), `is_active` (BooleanField), `date_joined` (DateTimeField), `email_confirmed` (BooleanField), `groups` → `Group`, `user_permissions` → `Permission`
